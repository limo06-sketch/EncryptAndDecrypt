## 📊 工作原理图解

```
PASSWORD + SALT
      ↓
┌──────────────────────────────────┐
│   初始哈希生成 (64字节)          │
└──────────────────────────────────┘
      ↓
┌──────────────────────────────────────────────────┐
│ 第1阶段：内存填充 (65,536块)                     │
│  ┌─────────────────────────────────────────┐    │
│  │ for i = 0 to 65535:                     │    │
│  │   memory[i] = Hash(previous + index)    │    │
│  └─────────────────────────────────────────┘    │
│  结果: 4MB 伪随机数据矩阵                       │
└──────────────────────────────────────────────────┘
      ↓
┌──────────────────────────────────────────────────┐
│ 第2阶段：多轮混合 (3轮 × 65,536块)             │
│ ┌──────────────────────────────────────────┐   │
│ │ for iter = 0 to 2:                       │   │
│ │   for i = 0 to 65535:                    │   │
│ │     prev = memory[i-1]                   │   │
│ │     ref  = memory[伪随机索引]            │   │
│ │     curr = memory[i]                     │   │
│ │     mixed = curr ⊕ prev ⊕ ref           │   │
│ │     mixed = SBOX(mixed)                  │   │
│ │     memory[i] = Hash(mixed)              │   │
│ └──────────────────────────────────────────┘   │
│ 关键特性：                                       │
│ • 每轮访问全部4MB内存                          │
│ • 伪随机访问模式                                │
│ • 内存成为性能瓶颈（不是CPU）                  │
└──────────────────────────────────────────────────┘
      ↓
┌──────────────────────────────────┐
│ 第3阶段：最终提取                │
│  final = memory[last] ⊕ memory[0]│
│  output = Hash(final)            │
└──────────────────────────────────┘
      ↓
    64字节密钥
      ↓
  分割为两个32字节密钥
  ├─ 加密密钥 (AES-256)
  └─ MAC密钥 (HMAC)
```

## 💡 为什么Argon2更安全？

### GPU破解的困难性

```
PBKDF2破解器:
┌─────────────────────────────┐
│ 迭代计数: 500,000           │
│ 内存使用: <100KB            │
│ GPU优势: 100-1000倍         │
│ 破解时间: 小时级别          │
└─────────────────────────────┘

Argon2破解器:
┌─────────────────────────────┐
│ 迭代轮数: 3 (每轮65K块)     │
│ 内存使用: 4MB               │
│ GPU优势: 1-2倍              │
│ 破解时间: 年级别            │
└─────────────────────────────┘
```

### 时间-空间权衡分析

```
PBKDF2:
├─ 降低迭代次数 → 加速破解
└─ 风险: 不可靠的安全性 ⚠️

Argon2:
├─ 降低内存 → 算法完全失效
├─ 增加时间 → 合法用户痛苦增加
└─ 无法有效权衡 → 可靠的安全性 ✅
```

## 🔧 配置参数说明

### 内存大小 (memory_size)

```cpp
const uint32_t memory_size = 65536;  // 当前设置
```

| 值 | 内存大小 | 耗时 | 适用场景 |
|-----|--------|------|---------|
| 16384 | 1MB | 快 | 移动设备 |
| 65536 | 4MB | 中等 | **通用** |
| 262144 | 16MB | 慢 | 高安全性 |

### 迭代次数 (iterations)

```cpp
const uint32_t iterations = 3;  // 当前设置
```

| 值 | 轮数 | 相对耗时 | 安全强度 |
|-----|------|---------|---------|
| 2 | 2轮 × 65K | 66% | 弱 |
| 3 | 3轮 × 65K | 100% | **中** |
| 4 | 4轮 × 65K | 133% | 强 |
| 5 | 5轮 × 65K | 166% | 很强 |

## 🛡️ 安全检查清单

- ✅ 使用强密码（≥12字符，混合大小写和数字）
- ✅ 每个实例自动生成随机盐值
- ✅ 使用AEAD进行认证加密
- ✅ 定期更新和审计加密代码
- ✅ 不要重用密钥（新密钥用新password）
- ✅ 安全存储派生的密钥（使用constantTimeMemZero清零）

## 🐛 常见问题

### Q: 为什么Argon2比PBKDF2慢？
A: Argon2故意设计得更慢，以提供更好的破解抗性。这个"慢"是特性，不是缺陷。

### Q: 可以调整参数以加速吗？
A: 可以，但要权衡安全性。参考上面的"优化建议"。

### Q: 硬件加速可以对抗Argon2吗？
A: 非常困难。内存访问是瓶颈，GPU和CPU在内存带宽上相近，所以GPU难以大幅加速。

### Q: 与标准Argon2规范有什么区别？
A: 这是一个简化的Argon2-inspired实现，保留了核心的内存困难特性。
